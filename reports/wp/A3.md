## A. As-is evidence
- `AppError` has exactly two exhaustive `when` sites: `Retryable.kt` and `DcWorker.kind()`; producers: `safeApiCall` (Connectivity/Http/Serialization), `DcWorker`+`ArticlesSyncWorker` (Serialization/Unknown). `Storage` has no producer. `UI` never sees `AppError` (repository collapses to Boolean).
- DEFECT (reproduced on HEAD code, scratch run): `SingleFlight.run` on a cancelled scope threw `IllegalStateException("Recursive update")` (`invokeOnCompletion` fired inside `ConcurrentHashMap.computeIfAbsent`).
- DEFECT (reproduced): a failing `SingleFlight` block cancelled a caller scope that has a plain `Job` (scope reported `isActive=false`).
- DEFECT (reproduced): `throttleFirst` delayed completion by the full window after upstream completed (344 ms for a 300 ms window).
- DEFECT (reproduced): `DcAlarmCodec.decodeList` returned `[]` if ANY entry had a removed receiver class / unknown zone / bad enum, so the next `FileDcAlarmStore.put` overwrote every stored alarm.
- `DcScheduler.schedule` ignored `id` for work while `cancel(id)`/`observe(id)` use it as the unique work name -> silent cancel/observe miss when `id != DcJobSpec.name` (`DcApplication` passes equal values).
- `DcMissedPolicy.FireOnce` has no effect on `DailyAt`/`WeeklyAt` (restore always re-arms the next occurrence). `DcAlarm` with a work trigger and default `missedPolicy` throws `IllegalStateException` (default evaluated before `require`), not `IllegalArgumentException`.
- `SingleFlight`, `JobRegistry`, `RetryPolicy` have NO production caller in `:app` (only `AppCoroutineScope` via `DcApplication`). `GlobalScope`: none. Static scopes in `DcAlarmReceiver`/`DcAlarmRestorer` are owned by their classes (see A3-design #6).
- `:runtime:scheduling` exposes `AppError` (`DcJobState.Failed`, `DcJobResult.Failure`) but declared `implementation(project(":foundation"))`.
