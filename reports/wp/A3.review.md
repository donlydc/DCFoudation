## Blocking (must fix)
1. `runtime/concurrency/.../SingleFlight.kt:34-35` — the fix for defect (b) adds a `SupervisorJob` as a permanent child of the caller's Job. That job never completes, so any scope that is joined can no longer finish.
   - Reproduced with the same code, coroutines 1.10.2, scratch only: `runBlocking { SingleFlight(this).run("k") { 1 } }` prints `1` but never returns (timeout, exit 124).
   - The same hang applies to `coroutineScope { SingleFlight(this) }` and to `runTest { SingleFlight(this) }`. HEAD did not hang, because `async` children finish. This is a behaviour regression of a public class.
   - No production caller exists today, and the existing tests use `backgroundScope` or `CoroutineScope(Unconfined)`, so none of them catches it. `SingleFlightContractTest` also misses it because `VirtualTimeScope` uses a detached root job.
   - Fix: make the supervisor per execution and complete it with the execution. This variant was checked in scratch and gives the right results:
     ```kotlin
     class SingleFlight<K : Any, V>(private val scope: CoroutineScope) {
         private val inFlight = ConcurrentHashMap<K, Deferred<V>>()
         suspend fun run(key: K, block: suspend () -> V): V {
             inFlight[key]?.let { return it.await() }
             val supervisor = SupervisorJob(scope.coroutineContext[Job])
             val candidate = CoroutineScope(scope.coroutineContext + supervisor)
                 .async(start = CoroutineStart.LAZY) { block() }
             val existing = inFlight.putIfAbsent(key, candidate)
             if (existing != null) { candidate.cancel(); supervisor.complete(); return existing.await() }
             candidate.invokeOnCompletion { supervisor.complete(); inFlight.remove(key, candidate) }
             return candidate.await()
         }
     }
     ```
     Scratch results: `runBlocking` returns; a failing block leaves a plain `Job` scope active; a cancelled scope gives `JobCancellationException` with no "Recursive update".
   - Add a regression test, for example `runTest { assertEquals(1, SingleFlight<String, Int>(this).run("k") { 1 }) }` plus a `coroutineScope { ... }` variant, so a lingering child fails the build instead of hanging.
   - Update the KDoc and the "private SupervisorJob child" wording in A3.md and A3-design.md #2 (`SingleFlight.kt:36-60` ref) to say per-execution.
