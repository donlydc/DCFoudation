# A3-design (R3.0) - Core and runtime contract design delta
- Agent: architecture-writer role (Sonnet 5.5). Status of every decision: **PROPOSED** (Opus finalizes in the final review). Evidence = source read in this session plus scratch-only JVM runs of the resulting code/tests (see `A3.md` section C; Gradle itself was not run).
- IDs: `MP:` = master-plan backlog. DEC ids are placeholders `DEC-A3-n` (final numbers assigned when merged into `23-decision-log.md`).

| # | Decision | Options (<=3) | Chosen (PROPOSED) |
|---|---|---|---|
| 1 | **AppError exhaustiveness / cause** (MP:CORE-01) | (a) sealed + exhaustive `when` without `else`, tests enumerate variants; (b) add a stable `code` to `AppError`; (c) redact `toString` | **(a).** Only two `when` sites exist (`Retryable.kt`, `DcWorker.kind()`); producers: `safeApiCall` (Connectivity/Http/Serialization), `DcWorker`/`ArticlesSyncWorker` (Serialization/Unknown); `Storage` has no producer. The WorkManager kind string lives in `:runtime:scheduling`, is lossy by design (`Http` -> code 0, no `cause`/`serverMessage`) and is pinned by per-variant tests. `cause` is diagnostic only, kept by reference, part of `equals`; data-class `toString` prints it, so never log `"$error"` (c) is a follow-up). |
| 2 | **SingleFlight cancel / failure / key lifetime** (MP:CON-01) | (a) run detached on the injected scope, key removed on completion; (b) ref-counted: cancel when last waiter leaves; (c) run on first caller | **(a)** + hardening: failure reaches every awaiter and is not cached (next call re-executes); a failing block must not cancel the caller's scope (run under a per-execution `SupervisorJob` that is completed with the execution, so it never keeps a joined scope such as `runBlocking`/`coroutineScope`/`runTest` from finishing); a cancelled scope must give `CancellationException`, not `IllegalStateException("Recursive update")` from `ConcurrentHashMap.computeIfAbsent` (use `putIfAbsent` + `invokeOnCompletion` outside the map callback). All callers cancelling does NOT stop the run (documented). |
| 3 | **JobRegistry lifecycle** (MP:CON-02) | (a) keep `synchronized` map + LAZY register-then-start; (b) `Mutex`; (c) per-registry child scope | **(a).** Contract: `launchLatest` cancels predecessor and a late-completing predecessor cannot evict its successor (identity check); `launchIfIdle` treats presence as busy; entries are removed on every completion (success, failure, cancel, scope cancel) so no orphan entry; no `close()` - cancelling the owner scope (`viewModelScope`) is the shutdown. `isRunning` is `isActive`, so false inside the LAZY window before `start()`. |
| 4 | **RetryPolicy** (MP:CON-03) | (a) keep public shape, internal `delayFor(attempt, random)` for tests; (b) public `Random` ctor parameter; (c) injectable delay function | **(a).** `maxAttempts` = total executions incl. the first; `delay_n = min(initial*factor^n, maxDelay) * (1 +/- jitter)` (cap before jitter, so max is `maxDelay*(1+jitter)`); `CancellationException` (incl. `TimeoutCancellationException` raised inside `block`) is never retried and the backoff `delay` is cancellable; the last failure is rethrown; `Flow.retrying` re-collects upstream from the start (duplicates possible). |
| 5 | **FlowSharing** (MP:CON-04) | (a) keep `WhileSubscribed(5 s)` default; (b) `Eagerly`; (c) `Lazily` | **(a).** Test start/stop/restart in virtual time. `throttleFirst` must complete when upstream completes (cancel the pending window timer instead of waiting out `window`). |
| 6 | **AppCoroutineScope ownership / shutdown** (MP:CON-07) | (a) process-lifetime, created once by the composition root, never cancelled in production; (b) add `close()`; (c) Hilt `@Singleton` binding | **(a).** Owner = `DcApplication` (only creator); features use `viewModelScope` or receive this scope, never build their own; no Android callback guarantees process shutdown, so no production cancel; tests/embedders stop it with `cancel()` (a `CoroutineScope` already provides it) and later `launch` calls are silently dropped. Uncaught `launch` failures go to `onUncaughtException` (must not throw; siblings survive via `SupervisorJob`); `async` failures surface only through `await`. Static receiver scopes in `DcAlarmReceiver`/`DcAlarmRestorer` stay (no DI in receivers; bounded by `goAsync` + 9 s timeout) - recorded as a PROPOSED deviation, not changed here. |
| 7 | **Work vs Alarm ownership, id identity** (MP:SCH-01/03) | (a) facade rejects `id != DcJobSpec.name`; (b) facade renames the spec to `id`; (c) document only | **(a).** Today `id` is ignored for work while `cancel(id)`/`observe(id)` address the unique work by name, so a mismatch silently breaks cancel/observe. Work: WorkManager owns persistence and retry; Alarm: `DcAlarmStore` owns intent, `AlarmManager` owns firing, `DcAlarmRestorer` re-arms. |
| 8 | **Idempotent enqueue** (MP:SCH-01) | (a) KEEP for `After` and `Every`, upsert-by-id for alarms (current); (b) REPLACE; (c) expose policy on the facade | **(a), documented.** `After` while unfinished: first request wins, later call is a no-op that still returns `Scheduled`. `Every`: changed interval/constraints are NOT applied (UPDATE unreachable through the facade; follow-up). Alarm `schedule` is an upsert by id (same request code + data URI => PendingIntent replaced); changing the receiver class under one id leaves the old PendingIntent, so cancel first. `restore()` ignores `DcMissedPolicy` for repeating alarms (always next occurrence). |
| 9 | **Persisted alarm list robustness** (MP:SCH-03) | (a) per-entry decode, drop only bad entries; (b) keep whole-list `runCatching`; (c) quarantine file | **(a).** (b) is a defect by reading: one entry whose receiver class/zone/enum is gone makes `decodeList` return `[]`, and the next `put` then overwrites every stored alarm. |
| 10 | **DcRetryPolicy vs RetryPolicy** (MP:SCH-06) | (a) keep both, document; (b) merge; (c) adapter | **(a).** `RetryPolicy`: in-process, per call, exception predicate, jittered coroutine `delay`, dies with the process. `DcRetryPolicy`: survives process death, OS-driven via `Result.retry()`, backoff is WorkManager's (>=10 s, linear or exponential, no jitter), ceiling enforced in `DcWorker` from input data. Both count `maxAttempts` as total executions. Do not nest `retrying` around a `DcJobResult.Retry` path (multiplicative attempts). |
| 11 | **Public API leak** | (a) `api(project(":foundation"))` in `:runtime:scheduling` (`DcJobState.Failed`/`DcJobResult.Failure` expose `AppError`); (b) hide `AppError` | **(a)** (applied). Same class of leak, NOT applied (outside instruction): `DispatcherProvider` (`AndroidDcScheduler`, `FileDcAlarmStore`), `Flow`, `KSerializer`, `ListenableWorker` in scheduling; `AppError` in `:data:network` (lane out of scope). |

Virtual-time approach (all concurrency tests): `runTest` + a scope built as `CoroutineScope(SupervisorJob() + StandardTestDispatcher(testScheduler))` and cancelled in `finally`, so `advanceUntilIdle()` works (a `backgroundScope` is ignored by it); a seeded `kotlin.random.Random` drives 100+ deterministic interleavings; no real sleeps. `:testing` cannot be used inside `:runtime:concurrency` tests (dependency direction), so dispatcher fakes are declared in-test.
